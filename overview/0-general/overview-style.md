# overview 的写法（六个课程仓库共用）

更新：2026-11-15。CI、CV、IHLT、IMAS、IML、PAR 的 `overview/` 都按这里来；这份文件在六个仓库里内容相同，改的话六份一起改。

## 1. 命名

- 文件和文件夹一律小写，单词之间用连字符：`code-notes.md`、`ex8-prisoners-dilemma/`。
- 只有 `README.md` 保持大写。
- 代码文件夹不受影响（例如 Python 包必须用下划线）。

## 2. 文件夹

```
overview/
  README.md        总索引
  0-general/       和具体作业无关的：todo.md（打开仓库先看）、环境、历史、写法（本文件）
  1-<部分>/        课程的各部分，按课程顺序编号（labs、project、work2、ec ……）
  2-<部分>/
  9-old/           归档，不再更新
```

- 一个部分里文件多（大约超过 5 个）时，再分带编号的子文件夹（例如 IML 的 `2-work3/1-task/`、`5-dbscan/`）；文件少就平放。
- 只在分支上的笔记（例如某个练习的分支）也放在同样的位置，用同样的名字。

## 3. 索引

每个有内容的文件夹都有 `README.md`，一张表：文件 | 内容。加文件时顺手更新索引。

## 4. 待办和现状：`0-general/todo.md`

每个仓库都有，打开仓库**先看这个**（`overview/README.md` 和根 README 的第一行都指向它）。第一屏回答"现在该做啥"：

```
# 待办和现状
更新：YYYY-MM-DD
## 现在做什么      最多 3 条，按先后
## 截止日期        | 什么 | 哪天 |（按日期排；不知道的写"待补"）
## 等别人          | 等谁 | 等什么 | 等到了以后我做什么 |
## 各部分现状      | 部分 | 状态 | 下一步 |
## 已决定不做      防止以后又重新讨论
```

- 每结束一段工作就更新它和"更新"日期；Claude 在仓库里干完活也顺手更新。
- 做完的事从"现在做什么"删掉，需要留痕的写进"各部分现状"。

## 5. 和团队的差异：`team-diff.md`

- 每个团队仓库一份，名字固定 `team-diff.md`；没有团队仓库的（例如 PAR）就不建。
- 这个团队仓库只对应一个部分，就放在那个部分的文件夹里；对应好几个部分，就放 `0-general/`。
- 骨架（语言跟着文件走）：

```
# 本地 vs 团队：差异表
团队仓库 / 本地文件夹 / 对照的版本（团队 commit 或 tag，本地 commit，日期）
## 总表        | 位置 | 本地 | 团队 | 类别 | 怎么处理 |
              类别：行为 / 接口 / 风格 / 本地独有 / 团队独有
## 1..n       按模块展开
## 可以从团队拿的 / 待移植
## 记录（按日期，可选）
```

## 6. 标题和语言

- 标题只写主题；需要日期时写在标题下面一行（`更新：YYYY-MM-DD`）。
- 已有的笔记有啥是啥，不翻译；新写的笔记用中文，代码名、术语保持原文。
